# Архитектура компонентов

Эти правила применяются к каждому React-компоненту, включая вложенные
и переиспользуемые компоненты.

## Структура компонента

Каждый компонент размещай в отдельной папке с именем компонента в PascalCase.
View и CSS Module обязательны. `usePresenter.ts` добавляй при наличии
собственной логики компонента.

Пример компонента с presenter.

```text
Button/
├── Button.tsx
├── usePresenter.ts
└── Button.module.css
```

`Button.tsx` выполняет роль View. Имя файла совпадает с именем папки
и экспортируемого компонента. Хук presenter называется `usePresenter`.
Стили компонента находятся в одноимённом CSS Module.

## View и presenter

- View содержит объявление компонента и возвращаемый JSX. При наличии
  presenter вызывает `usePresenter` и использует его результат.
- `usePresenter` принадлежит своему компоненту. Каждый компонент использует
  только собственный presenter. Это правило действует и для вложенных
  и общих компонентов, включая обращения через их вспомогательные файлы.
- Во View разрешены импорты `usePresenter`, CSS Module, подкомпонентов
  и типов, необходимых для JSX и props.
- View использует props, а при наличии presenter также его данные
  и обработчики.
- Состояние, эффекты, обработчики событий, валидацию, бизнес-вычисления,
  подготовку данных и обращения к API размещай в `usePresenter`.
- Во View допустима логика отображения, включая `.map()` для вывода списков,
  условный JSX и выбор CSS-классов.

## Разделение логики

Для удобства чтения разделяй сложную логику presenter на небольшие файлы
по ответственности. Размещай их рядом с `usePresenter.ts`.
Presenter вызывает эти функции и хуки и формирует результат для View.

Логику, нужную нескольким компонентам, выноси в отдельный общий хук
или функцию. Presenter разных компонентов могут использовать эту логику.

## Вложенные компоненты

Подкомпонент, используемый одним родителем, размещай внутри папки родителя
в собственной папке. Для него обязательны View и CSS Module,
а `usePresenter` добавляется при наличии собственной логики.
Применяй это правило на любой глубине вложенности.

## Общие компоненты и область использования

Общие компоненты конкретной части приложения размещай в папке `components`
в ближайшем общем родительском каталоге двух или более потребителей.
Внутри `components` каждый общий компонент имеет свою папку и ту же структуру.

Для `P/components/Shared` разрешены потребители в каталоге `P` и во всём
его поддереве. Это ограничение действует также при реэкспортах.
При появлении потребителя вне этой области переноси общий компонент
в `components` подходящего общего родительского каталога.

Пример структуры, где `Overview` и `Details` используют `StatusBadge`,
а `Summary` принадлежит `Overview`. Здесь presenter есть у компонентов
с собственной логикой, включая `StatusBadge`. `Summary` отображает props.

```text
Dashboard/
├── Dashboard.tsx
├── usePresenter.ts
├── Dashboard.module.css
├── Overview/
│   ├── Overview.tsx
│   ├── usePresenter.ts
│   ├── Overview.module.css
│   └── Summary/
│       ├── Summary.tsx
│       └── Summary.module.css
├── Details/
│   ├── Details.tsx
│   ├── usePresenter.ts
│   └── Details.module.css
└── components/
    └── StatusBadge/
        ├── StatusBadge.tsx
        ├── usePresenter.ts
        └── StatusBadge.module.css
```

`StatusBadge` доступен компонентам внутри `Dashboard` и его подпапок.
`Summary` используется своим родителем `Overview`.

## UI-kit

Общие UI-компоненты приложения размещай в `src/ui-kit`, например `Button`,
`Input` или `Modal`. Они доступны компонентам во всём дереве `src`.

Для каждого UI-kit компонента создавай отдельную папку и соблюдай общие
правила структуры, View, CSS Module и необязательного `usePresenter`.
