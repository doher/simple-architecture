# Правила оформления коммитов и веток

## Сообщения коммитов

Для каждого создаваемого коммита соблюдай Conventional Commits 1.0.0-beta.2.
[Спецификация на русском](https://www.conventionalcommits.org/ru/v1.0.0-beta.2/)

Используй один из вариантов заголовка.

```text
<type>: <описание>
<type>(<scope>): <описание>
```

- Выбирай `feat` для новой функциональности, `fix` для исправления ошибки.
- Пиши заголовок, тело и footer коммита на английском языке.
- Описание кратко передаёт суть изменения.
- Необязательный `scope` обозначает затронутую часть проекта.
- Дополнительные пояснения помещай в тело после пустой строки.
- Необязательный footer отделяй пустой строкой. В нём указывай связанную
  существующую задачу, например `Fixes #42`, и относящиеся к ней метаданные.
- При отсутствии связанной задачи помещай пояснения в тело сообщения.
- Нарушение совместимости отмечай в начале тела или footer строкой
  `BREAKING CHANGE: <что изменилось в API>`. Это применимо к любому типу.
- Разделяй независимые изменения на отдельные коммиты, когда это возможно.

## Типы и область изменений

Следующие обозначения и их написание приняты в этом проекте.
Типы и scope пиши строчными латинскими буквами. Для составного scope
используй kebab-case, например `user-profile`.

| Тип           | Назначение                               |
| ------------- | ---------------------------------------- |
| `feat`        | Новая функциональность                   |
| `fix`         | Исправление ошибки                       |
| `docs`        | Документация и инструкции агентам        |
| `style`       | Форматирование кода                      |
| `refactor`    | Переработка кода с сохранением поведения |
| `perf`        | Улучшение производительности             |
| `test`        | Тесты                                    |
| `build`       | Сборка и зависимости                     |
| `ci`          | Конфигурация CI                          |
| `chore`       | Обслуживание проекта и инструментов      |
| `revert`      | Отмена предыдущего изменения             |
| `improvement` | Улучшение существующей реализации        |

Выбирай тип по содержимому конкретного коммита.

```text
feat(profile): add name editing
fix(form): correct required field validation
chore(tooling): configure Biome and TypeScript checks
docs(agents): document commit and branch conventions
```

Пример несовместимого изменения с пояснением в теле.

```text
refactor(store): change store initialization

BREAKING CHANGE: createStore now accepts an options object instead of a string.
```

## Имена веток

Это дополнительное соглашение проекта. Для рабочих веток используй шаблон
`<type>/<short-description>`.

- Выбирай тип из таблицы по основной задаче ветки.
- Пиши описание на английском в нижнем регистре, разделяя слова дефисами.
- Используй короткое описание цели работы.
- Основная ветка проекта — `main`.

Примеры рабочих веток.

```text
feat/user-profile
fix/form-validation
chore/update-tooling
docs/agent-rules
```
