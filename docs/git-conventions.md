# Правила оформления коммитов и веток

## Сообщения коммитов

Соблюдай [Conventional Commits 1.0.0-beta.2](https://www.conventionalcommits.org/ru/v1.0.0-beta.2/).

```text
<type>: <description>
<type>(<scope>): <description>
```

- Выбирай `feat` для новой функциональности, `fix` для исправления ошибки.
- Пиши заголовок, тело и footer коммита на английском языке.
- Тип и scope пиши строчными латинскими буквами; составной scope —
  в kebab-case, например `user-profile`.
- Необязательные тело и footer отделяй пустой строкой. В footer указывай
  связанную существующую задачу, например `Fixes #42`, и метаданные.
- Нарушение совместимости отмечай в начале тела или footer строкой
  `BREAKING CHANGE: <description>` при любом типе коммита.
- Разделяй независимые изменения на отдельные коммиты, когда это возможно.

Допустимые типы: `feat`, `fix`, `docs`, `style`, `refactor`, `perf`, `test`,
`build`, `ci`, `chore`, `revert`, `improvement`.

## Имена веток

Основная ветка — `main`. Формат рабочей ветки:

```text
<type>/<short-description>
```

Тип выбирай из списка выше по основной задаче ветки.
Описание пиши на английском в нижнем регистре, разделяя слова дефисами.
